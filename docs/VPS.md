# VPS.md — план переноса на VPS и оценка готовности

Обновлено: 2026-09-01. Оценка готовности: **~70%** — вся логика автономии
готова и не зависит от Mac; осталась адаптация инфраструктуры (systemd,
Chrome под Linux) и три фикса надёжности из BACKLOG.

## Что уже VPS-ready

- Вся логика в Python/uv, git-репозиторий, `.env` переносится копированием.
- LLM-слой внутри (api.z.ai) — работает откуда угодно.
- SQLite — файл, переносится.
- Автопилот/воркер не зависят от GUI-сессии пользователя (nohup/launchd).
- Гейты денег/безопасности в коде (лимит 3/день, потолок 500 ₽, рабочие
  часы 8–23, анти-инъекция, честные тексты).

## Блокеры (нужно сделать ДО переезда)

1. **P1-A reconnect Chrome** — на VPS Chrome будет падать чаще; воркер
   обязан сам переподключаться/перезапускать Chrome (на Linux это же
   закроет и смерть дисплея Xvfb).
2. **P0-B остаток: рабочие часы воркера-мониторинга** — 24/7-мониторинг
   с датацентр-IP = сильный бот-сигнал; обязательно 8–23 и для ленты.
3. **P0-A lock-файл + WAL** — защита от задвоения процессов.
4. **Linux-скрипты**: `start-chrome.sh` под Linux (chrome + Xvfb —
   ТОЛЬКО headful через виртуальный дисплей, headless детектится),
   `autopilot_cron.sh` без launchd → systemd timer + PATH.
5. **systemd-юниты**: profi-worker.service (Restart=always — заодно
   усилит P1-A), profi-autopilot.timer (*/2).

## Чек-лист миграции

- [ ] VPS: **Россия** (Profi-ру — резкая смена страны IP = риск
      переквалификации сессии). Рекомендации: Yandex Cloud / Selectel /
      Timeweb, 1 vCPU / 1–2 ГБ достаточно.
- [ ] Таймзона Europe/Moscow (рабочие часы/полуночь лимита считаются
      по локальному времени).
- [ ] Установить: python3.11+, uv, google-chrome-stable, xvfb.
- [ ] Перенести: git-репо, `.env`, **chrome-профиль main** (куки =
      доступ к аккаунту! только по SSH-ключам, scp/shadow копия).
- [ ] systemd-юниты + таймер; проверить heartbeat в logs/launchd.log.
- [ ] Прогрев: первые 1–2 дня ритм ленты 180–240 с (реже), отклики
      вручную-полуавто, потом вернуть 90–120 с.
- [ ] Безопасность VPS: SSH только по ключу, ufw (закрыть всё кроме
      ssh), fail2ban. Профиль+`.env` = полноценный захват аккаунта при
      компрометации.
- [ ] Наблюдение: `tail -f logs/watch.log` / автопилот-журнал;
      пополнение баланса — по-прежнему вручную владельцем.

## Риски переезда (принять осознанно)

- IP сменится с домашнего на датацентровый: у Профи нет прямых
  признаков запрета, но ASN датацентра + та же сессия = вопрос.
  Смягчение: RU-VPS, прогрев, тот же Chrome/User-Agent.
- Потеря «бесплатного присутствия» домашнего IP; зато 24/7 аптайм.
- Если сессия слетит — перелогин руками через VNC/noVNC к Xvfb-дисплею
  (раз в ~год по сроку печенек).

## Вердикт

Архитектура переезд не требует (никаких Mac-only завязок в логике).
Работа: ~1 день на фиксы P0-A/P1-A/P0-B + Linux-скрипты/systemd,
~1 час на сам перенос, 1–2 дня щадящего прогрева. До фиксов P1-A/P0-B
переезжать НЕ рекомендую — на VPS без присмотра система умрёт при первом
же падении Chrome, а ночной 24/7-мониторинг с нового IP повысит риск
блока.
